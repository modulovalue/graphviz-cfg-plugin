# `cfg` plugin regression suite

Fixture-based golden tests that pin the layout the `cfg` engine produces, so
future changes can be checked for "things stay more or less the same".

## How it works

Each fixture is a small `.dot` graph under `fixtures/<category>/`. For every
fixture the runner:

1. **smoke-tests** that `dot -Kcfg -Tsvg` renders without crashing, and
2. diffs the canonical **`-Tdot`** output — node positions, edge spline points,
   and cluster bounding boxes / label positions — against a committed **golden**
   snapshot in `golden/<category>/`.

Layout is deterministic for a fixed graphviz version, so any change in geometry
(a node moves, an edge reroutes, a cluster box resizes) surfaces as a diff.

## Categories

| Category | What it exercises |
|---|---|
| `layout` | Pure node sizing & placement: single node, chains, fan-out, disconnected components, shapes, multi-line/record labels. No tricky edges. |
| `edges` | Edge routing: branch, merge, back-edge, self-loop, `cfgbias`, diamonds, parallel edges, long (level-skipping) edges, nested loops, colored edges. |
| `subgraphs` | `subgraph cluster_*` boxes: single, nested, siblings, multi-entry, multi-exit, label justification (default-left vs explicit), unlabeled, styled, all-in-one, deep nesting, two-region CFG. |
| `ports` | `node:port` attachment: record switch fan-out, nested record `true`/`false` cells, compass (`:e`/`:w`), ports on both ends. |
| `realworld` | A full Dart IL CFG (HTML labels + colored branches + biases together). |

## Layout

Three parallel trees, one entry per fixture in each:

```
test/fixtures/<category>/<name>.dot   # the input graph
test/golden/<category>/<name>.dot     # committed -Tdot snapshot (the assertion)
test/render/<category>/<name>.pdf     # a viewable PDF render (eyeball aid)
```

## Usage

```sh
test/run.sh                  # run everything
test/run.sh subgraphs ports  # only named categories
DOT=/path/to/dot test/run.sh # use a specific graphviz

test/gen-golden.sh           # regenerate goldens (after a reviewed change)
test/render.sh               # (re)build test/render/*.pdf, mirroring fixtures/
test/render.sh --overview    # also build the combined fixtures-overview.pdf
test/compare-baseline.sh     # diff flat layout/edges vs git HEAD (see below)
```

The `render/` PDFs and `fixtures-overview.pdf` are eyeball aids, regenerated by
`test/render.sh`; only `fixtures/` and `golden/` are needed to run the tests.

`run.sh` exits non-zero and lists the offending fixtures on any crash, missing
golden, or geometry diff. If a diff is **intended**, eyeball it, then re-bless
with `test/gen-golden.sh` (optionally per-category) and commit the new goldens.

## Before/after guarantee

`compare-baseline.sh` builds the `git HEAD` version of the plugin and the
current working tree, renders the `layout`, `edges`, and `realworld` fixtures
with each, and diffs them. These categories predate the cluster/port work, so
they **must stay byte-for-byte identical** — the script asserts that. (Clusters
and ports are new capabilities with no baseline; their goldens were captured and
visually reviewed when the features landed.)

## Notes

- Goldens are tied to the installed graphviz version (coordinates are absolute).
  Bumping graphviz will require regenerating them; review the diff first.
- `-Tdot` rather than `-Tplain` is used as the snapshot because `-Tplain` omits
  cluster boxes and labels, which the subgraph tests need to verify.
